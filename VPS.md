# МАИ.Команда на Linux VPS

Сайт открывается по публичному IPv4. nginx отдаёт интерфейс и принимает запросы к `/api/` на том же адресе. PostgreSQL и FastAPI доступны только внутри сети Docker.

## Подготовка сервера

Понадобятся SSH-доступ, Docker Engine и плагин Docker Compose версии 2.24.4 или новее. Проверить установку можно командами `sudo docker info` и `sudo docker compose version`. Инструкции по установке Docker с плагином Compose есть для [Ubuntu](https://docs.docker.com/engine/install/ubuntu/) и [Debian](https://docs.docker.com/engine/install/debian/).

По умолчанию сайт занимает TCP-порт 80. Разрешите входящие подключения к нему в панели VPS и, если настроена фильтрация на сервере, в её правилах. Сохраните действующее правило SSH. Если порт 80 уже занят, ниже показан запуск на другом порту.

## Первый запуск из репозитория

Поместите свой файл `.env` с `POSTGRES_PASSWORD` в корень проекта на сервере. При обновлении существующей базы сохраните её имя (`POSTGRES_DB`) и имя пользователя (`POSTGRES_USER`).

В терминале VPS перейдите в корень клонированного репозитория, где лежат `compose.yaml` и `vps.sh`, и выполните:

```sh
sudo sh vps.sh
```

Для обращения к сайту замените `IP` в адресе ниже на публичный IPv4 из панели провайдера.

Скрипт берёт пароль PostgreSQL из `.env`. При переходе со старой версии оставьте прежний файл `.env.vps` рядом на первый запуск: скрипт проверит подключение к существующей базе и при необходимости установит её пользователю пароль из `.env`. База хранится в томе `mai-team-vps_pgdata`. При первом запуске с этой версией в каталог добавляются три опубликованных проекта с отметкой «Демо», у каждого свой автор и открытая роль. Это работает и при обновлении существующей базы. Повторный запуск сохраняет изменения и не создаёт копии.

Откройте **`http://IP/`** с другого устройства. Для проверки с сервера выполните:

```sh
curl -fsS http://127.0.0.1/api/health
```

Ответ `{"detail":"ok"}` означает, что работают nginx, FastAPI и подключение к PostgreSQL. Если проверка проходит, а сайт снаружи недоступен, проверьте IPv4 и входящий порт в панели VPS. Для HTTPS по публичному IPv4 включите режим ниже.

Чтобы открыть сайт напрямую на другом порту, например 8080, установите `VPS_PORT=8080` в `.env` через `sudoedit .env` и снова выполните `sudo sh vps.sh`. Откройте выбранный порт и добавьте его к адресу сайта и проверки, например `http://IP:8080/`.

## HTTPS по IPv4 без домена

Откройте для входящих TCP-соединений порты 80 и 443 в панели провайдера и в правилах сети VPS. В этом режиме оба порта занимает Caddy. Если их уже использует другой сайт или прокси, сначала согласуйте конфигурацию с ним.

В основном файле `.env` рядом с `vps.sh` задайте публичный IPv4 из панели провайдера. Замените пример своим адресом:

```dotenv
VPS_PUBLIC_IPV4=203.0.113.10
```

Затем примените настройки:

```sh
sudo sh vps.sh
```

Откройте `https://ВАШ_IP/`. Проверьте с другого компьютера командой `curl https://ВАШ_IP/api/health`. При действительном сертификате и доступной базе ответ будет `{"detail":"ok"}`. Caddy получает сертификат в фоне, поэтому первый запрос может потребовать короткого ожидания. Ход выпуска можно увидеть командой `sudo sh vps.sh logs --tail 80 https`.

Caddy перенаправляет HTTP на HTTPS, продлевает сертификат и хранит ключи и учётную запись ACME в томе Docker `caddy_data`. Оставьте порты доступными для следующих проверок. Публичный сертификат привязан к указанному IP. [Сертификаты Let's Encrypt для IP](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability/).

В старых установках адрес из `.env.https` продолжает действовать, пока в основном `.env` не задан `VPS_PUBLIC_IPV4`. Чтобы вернуться к HTTP, сначала выполните `sudo sh vps.sh down`, затем задайте в `.env` пустое значение `VPS_PUBLIC_IPV4=` и снова выполните `sudo sh vps.sh`.

## Тестовые профили

На VPS создаются три демопрофиля — `demo.engineer@example.com`, `demo.designer@example.com` и `demo.analyst@example.com`. Чтобы включить вход для новых демопрофилей, задайте в `.env` отдельный `VPS_DEMO_PASSWORD` длиной от 10 до 128 символов и выполните `sudo sh vps.sh`. Если оставить его пустым, демопроекты появятся в каталоге, а вход под новыми демопрофилями можно будет включить позже. Для демопрофилей, у которых уже был пароль, продолжает действовать прежний пароль. В старых установках он записан в `.env.vps.demo`. Если адрес уже принадлежал пользователю, новый тестовый профиль получит адрес с числом перед `@`, например `demo.engineer.1@example.com`. Точный адрес виден модератору в поле контактов демопроекта.

## Назначить модератора

Зарегистрируйте личный аккаунт на сайте. На запущенном VPS выполните из каталога проекта, подставив email этого аккаунта:

```sh
sudo sh vps.sh moderator user@example.com
```

После подтверждения обновите страницу сайта. Пароль аккаунта остаётся тем, который вы указали при регистрации. При повторном запуске команда сообщит, что права уже выданы.

## Управление

Все команды выполняются из корня репозитория на VPS. Чтобы обновить сайт из текущей ветки, выполните:

```sh
git pull --ff-only
sudo sh vps.sh
```

| Действие | Команда |
| --- | --- |
| Состояние контейнеров, включая миграции | `sudo sh vps.sh ps -a` |
| Последние записи журналов | `sudo sh vps.sh logs --tail 100` |
| Остановить сайт с сохранением базы | `sudo sh vps.sh down` |
| Запустить снова | `sudo sh vps.sh` |

После перезагрузки VPS Docker поднимает работавшие контейнеры, если служба Docker включена в автозагрузку. Для включения на сервере с systemd выполните `sudo systemctl enable docker`.
