# МАИ.Команда на Linux VPS

Сайт открывается по публичному IPv4. nginx отдаёт интерфейс и принимает запросы к `/api/` на том же адресе. PostgreSQL и FastAPI доступны только внутри сети Docker.

## Подготовка сервера

Понадобятся SSH-доступ, Docker Engine и плагин Docker Compose версии 2.24.4 или новее. Проверить установку можно командами `sudo docker info` и `sudo docker compose version`. Инструкции по установке Docker с плагином Compose есть для [Ubuntu](https://docs.docker.com/engine/install/ubuntu/) и [Debian](https://docs.docker.com/engine/install/debian/).

По умолчанию сайт занимает TCP-порт 80. Разрешите входящие подключения к нему в панели VPS и, если настроена фильтрация на сервере, в её правилах. Сохраните действующее правило SSH. Если порт 80 уже занят, ниже показан запуск на другом порту.

## Первый запуск из репозитория

В терминале VPS перейдите в корень клонированного репозитория, где лежат `compose.yaml` и `vps.sh`, и выполните:

```sh
sudo sh vps.sh
```

Для обращения к сайту замените `IP` в адресе ниже на публичный IPv4 из панели провайдера.

При первом запуске скрипт создаёт файл `.env.vps` со случайным паролем PostgreSQL. Docker собирает приложение, применяет миграции и ждёт ответа от базы через nginx. Сохраните `.env.vps` для следующих запусков. База хранится в томе `mai-team-vps_pgdata`. При первом запуске с этой версией в каталог добавляются три опубликованных проекта с отметкой «Демо», у каждого свой автор и открытая роль. Это работает и при обновлении существующей базы. Повторный запуск сохраняет изменения и не создаёт копии.

Откройте **`http://IP/`** с другого устройства. Для проверки с сервера выполните:

```sh
curl -fsS http://127.0.0.1/api/health
```

Ответ `{"detail":"ok"}` означает, что работают nginx, FastAPI и подключение к PostgreSQL. Если проверка проходит, а сайт снаружи недоступен, проверьте IPv4 и входящий порт в панели VPS. Этот режим использует обычный HTTP. Для работы с реальными паролями настройте HTTPS. При использовании HTTPS-прокси на том же сервере задайте в `.env.vps` строки `VPS_BIND_IP=127.0.0.1` и `VPS_PORT=8080`, повторно запустите скрипт и направьте прокси на `http://127.0.0.1:8080`.

Чтобы открыть сайт напрямую на другом порту, например 8080, установите `VPS_PORT=8080` в `.env.vps` через `sudoedit .env.vps` и снова выполните `sudo sh vps.sh`. Откройте выбранный порт и добавьте его к адресу сайта и проверки, например `http://IP:8080/`.

## Тестовые профили

Войти можно под любым из трёх авторов: `demo.engineer@example.com`, `demo.designer@example.com` или `demo.analyst@example.com`. У всех обычные права участника. Общий для этих профилей пароль генерируется отдельно на каждом VPS. Посмотреть его на сервере:

```sh
sudo cat .env.vps.demo
```

Для входа скопируйте значение после `VPS_DEMO_PASSWORD=`. Сохраните файл вместе с `.env.vps`. Если адрес уже принадлежал пользователю, новый тестовый профиль получит адрес с числом перед `@`, например `demo.engineer.1@example.com`. Точный адрес виден модератору в поле контактов демопроекта.

## Первый модератор

Зарегистрируйте свой аккаунт на сайте. Чтобы он мог публиковать проекты из очереди, откройте PostgreSQL из каталога проекта:

```sh
sudo sh vps.sh exec db psql -U mai -d mai
```

Выполните в psql, указав email зарегистрированного аккаунта по запросу:

```sql
\prompt 'Email: ' account_email
UPDATE users SET role = 'moderator' WHERE email = lower(:'account_email') RETURNING email;
\q
```

Проверьте, что команда вернула ваш email, затем обновите страницу сайта.

## Управление

Все команды выполняются из корня репозитория на VPS. Чтобы обновить сайт из текущей ветки, выполните:

```sh
git pull --ff-only
sudo sh vps.sh
```

| Действие | Команда |
| --- | --- |
| Состояние контейнеров, включая миграции | `sudo sh vps.sh ps -a` |
| Последние записи журналов | `sudo sh vps.sh logs --tail 100` |
| Остановить сайт с сохранением базы | `sudo sh vps.sh down` |
| Запустить снова | `sudo sh vps.sh` |

После перезагрузки VPS Docker поднимает работавшие контейнеры, если служба Docker включена в автозагрузку. Для включения на сервере с systemd выполните `sudo systemctl enable docker`.
